# 04 — แนวข้อสอบปากเปล่าและ Live Coding

เอกสารนี้เป็นคู่มือเตรียมสอบกลางสำหรับสมาชิกทุกคนในทีม ใช้เนื้อหาและเกณฑ์เดียวกัน ไม่แบ่งชุดคำถามตามผู้เขียนหรือผู้รับผิดชอบไฟล์ สมาชิกทุกคนควรอธิบายภาพรวม โค้ดทั้ง 4 โมดูล และการเชื่อมต่อระหว่างไฟล์ได้

## วิธีตอบให้ได้คะแนน

ใช้โครงสร้าง 4 ส่วน:
1. **หน้าที่:** โค้ดส่วนนี้ทำอะไร
2. **Input:** รับข้อมูลอะไรและชนิดข้อมูลอะไร
3. **Process:** ทำงานตามลำดับอย่างไร
4. **Output/connection:** return อะไร และไฟล์ไหนนำไปใช้ต่อ

อย่าตอบแค่ว่า “ใช้คำนวณ” ต้องอธิบายว่าคำนวณจากอะไรและผลลัพธ์ถูกส่งไปที่ไหน

## คำถามภาพรวมระบบ

**Q1: โปรแกรมนี้ทำงานอย่างไรตั้งแต่ต้นจนจบ?**

แนวตอบ: main.py แสดงเมนูและรับ input จากผู้ใช้ จากนั้นโหลดราคาหุ้นจาก Yahoo Finance หรือ sample CSV นำราคาปิดไปคำนวณ daily returns คำนวณ volatility จำลองเส้นทางพอร์ตด้วย Historical Bootstrap Monte Carlo ประเมินความเสี่ยง และสร้างรายงาน TXT

**Q2: ทำไมแยกเป็นหลายไฟล์?**

แนวตอบ: แยกหน้าที่เพื่อให้แต่ละโมดูลรับผิดชอบงานเฉพาะ แก้ไขและทดสอบได้ง่าย main.py ทำหน้าที่เชื่อมกระบวนการ ส่วนไฟล์อื่นทำงานด้านข้อมูล การจำลอง และความเสี่ยง

**Q3: ข้อมูลเดินทางข้ามไฟล์อย่างไร?**

แนวตอบ: main.py เรียกฟังก์ชันและส่ง argument เข้าไป ฟังก์ชันประมวลผลแล้ว return ค่าให้ main.py เก็บในตัวแปร จากนั้นส่งต่อให้ฟังก์ชันถัดไป

## คำถาม Python

**Q4: Parameter กับ argument ต่างกันอย่างไร?**

Parameter คือชื่อตัวแปรในนิยามฟังก์ชัน ส่วน argument คือค่าจริงที่ส่งตอนเรียกใช้

**Q5: return ต่างจาก print อย่างไร?**

return ส่งค่ากลับให้โค้ดส่วนที่เรียกใช้สามารถเก็บหรือคำนวณต่อได้ ส่วน print แสดงข้อความบนหน้าจอ ไม่ได้ใช้แทนค่าที่ return

**Q6: try/except ใช้ทำอะไร?**

ใช้จัดการข้อผิดพลาดที่คาดการณ์ได้ เช่น ผู้ใช้พิมพ์ตัวอักษรแทนตัวเลข เพื่อให้โปรแกรมแจ้งเตือนและทำงานต่อได้ แทนที่จะหยุดทันที

**Q7: list กับ dictionary ต่างกันอย่างไร?**

list เก็บข้อมูลเป็นลำดับและเข้าถึงด้วย index ส่วน dictionary เก็บข้อมูลเป็นคู่ key-value และเข้าถึงด้วย key

**Q8: ทำไมต้องใช้ if __name__ == "__main__"?**

เพื่อให้โค้ดทดสอบหรือจุดเริ่มโปรแกรมทำงานเมื่อเปิดไฟล์โดยตรง แต่ไม่ทำงานเมื่อไฟล์นั้นถูก import จากไฟล์อื่น

## คำถามคณิตศาสตร์/การเงิน

**Q9: Daily Return คำนวณอย่างไร?**

`(ราคาวันนี้ / ราคาวันก่อน) - 1` เช่น 110 เทียบกับ 100 ได้ 0.10 หรือ +10%

**Q10: Volatility หมายถึงอะไร?**

วัดว่าผลตอบแทนกระจายหรือแกว่งจากค่าเฉลี่ยมากแค่ไหน ไม่ได้บอกว่าผลตอบแทนเป็นบวกหรือลบ

**Q11: ทำไม annualize ด้วย sqrt(252)?**

โค้ดใช้สมมติฐาน 252 วันทำการซื้อขายต่อปี และแปลง standard deviation รายวันเป็นรายปีด้วยรากที่สองของจำนวนวัน

**Q12: Monte Carlo คืออะไร?**

วิธีจำลองหลายสถานการณ์โดยใช้การสุ่ม เพื่อดูการกระจายของผลลัพธ์ที่อาจเกิดขึ้นภายใต้สมมติฐานที่กำหนด

**Q13: Historical Bootstrap ต่างจากการสุ่มแบบ Normal Distribution อย่างไร?**

Bootstrap สุ่มค่าจากผลตอบแทนจริงในอดีตที่มีอยู่ในชุดข้อมูล ส่วน Normal approach จะสุ่มจากการแจกแจงที่กำหนดพารามิเตอร์ เช่น mean และ standard deviation

**Q14: seed=42 มีไว้ทำไม?**

เพื่อให้ลำดับการสุ่มทำซ้ำได้ เมื่อใช้ข้อมูลและ seed เดิม จึงช่วยให้ทดสอบและเปรียบเทียบผลได้

**Q15: VaR คืออะไร?**

เป็นค่าระดับเปอร์เซ็นไทล์ของผลขาดทุนจากชุดผลจำลองตาม confidence level ที่กำหนด ไม่ใช่การรับประกันขาดทุนสูงสุด

**Q16: Maximum Drawdown คืออะไร?**

เปอร์เซ็นต์การลดลงจากจุดสูงสุดก่อนหน้าไปยังมูลค่าที่ต่ำกว่าในภายหลัง โดยเลือกค่าการลดลงที่มากที่สุดในเส้นทางนั้น

## คำถามเจาะลึกโค้ด — ข้อสอบกลางของทีม

คำถามในส่วนนี้ใช้กับสมาชิกทุกคนเหมือนกัน ไม่แบ่งตามผู้เขียนหรือผู้รับผิดชอบโมดูล การแบ่งงานมีไว้จัดการการพัฒนาเท่านั้น ไม่ได้หมายความว่าสมาชิกจะศึกษาเฉพาะไฟล์ของตนเองได้ ในการสอบ สมาชิกทุกคนควรสามารถเปิดไฟล์ที่เกี่ยวข้อง อธิบายการทำงาน และบอกผลกระทบต่อโมดูลที่เชื่อมต่อกันได้

ดูชื่อไฟล์ ฟังก์ชัน และเลขบรรทัดได้ที่ [05 — Code Location Map](05-code-location-map.md)

### คำถามเกี่ยวกับ main.py

**Q17: ทำไมต้องตรวจ len(daily_returns) < 2?**

เพราะ calculate_volatility ใช้ sample variance ซึ่งต้องมีข้อมูลอย่างน้อย 2 ค่า และราคาอย่างน้อย 3 วันจึงได้ daily returns 2 ค่า

**Q18: run_monte_carlo คืนค่าอะไร?**

คืน list ซ้อน list: list ชั้นนอกแทนแต่ละ simulation ส่วน list ชั้นในแทนมูลค่าพอร์ตตั้งแต่วันเริ่มต้นถึงวันสุดท้าย

**Q19: ทำไมแต่ละ path มีจำนวนค่า trading_days + 1?**

เพราะบันทึกเงินลงทุนเริ่มต้นไว้หนึ่งค่าก่อนจำลองวันแรก แล้วจึงเพิ่มมูลค่าหลังจำลองแต่ละวัน

**Q20: ถ้าเปลี่ยน seed จะเกิดอะไรขึ้น?**

ลำดับผลตอบแทนที่สุ่มมีโอกาสเปลี่ยน ทำให้เส้นทางและผล risk เปลี่ยน แต่โครงสร้างขั้นตอนคำนวณยังเหมือนเดิม



### คำถามเกี่ยวกับ data_analysis.py

**Q21: normalize_ticker() มีหน้าที่อะไร?**

แนวตอบ: ทำความสะอาดรหัสหุ้น เช่น ตัดช่องว่างหัวท้ายและแปลงเป็นตัวพิมพ์ใหญ่ เพื่อให้การเปรียบเทียบรหัสหุ้นสม่ำเสมอ อยู่ในไฟล์ data_analysis.py

**Q22: load_stock_data() ใช้แหล่งข้อมูลใด และมีทางเลือกสำรองอย่างไร?**

แนวตอบ: พยายามดาวน์โหลดราคาหุ้นจาก Yahoo Finance และจัดเก็บ/อ่านข้อมูลผ่านไฟล์ CSV cache หากดาวน์โหลดไม่ได้จะพยายามใช้ข้อมูลที่มีอยู่ในเครื่องตามเงื่อนไขของโปรแกรม

**Q23: ทำไมต้องตรวจสอบ Close ว่าเป็นตัวเลข finite และมากกว่าศูนย์?**

แนวตอบ: เพื่อป้องกันข้อมูลหาย ค่าที่ไม่ใช่ตัวเลข เช่น NaN หรือ infinity และราคาที่ไม่สมเหตุสมผลไม่ให้ไหลไปทำให้การคำนวณผลตอบแทนผิดพลาด

### คำถามเกี่ยวกับ simulation.py

**Q24: Sample variance ต่างจาก population variance อย่างไร?**

แนวตอบ: Sample variance หารด้วย n-1 เพื่อประมาณความแปรปรวนของประชากรจากตัวอย่าง ส่วน population variance หารด้วย n โค้ด calculate_volatility() ใช้ n-1

**Q25: ทำไม annualized volatility จึงคูณด้วย sqrt(252)?**

แนวตอบ: ภายใต้สมมติฐานวันซื้อขาย 252 วันต่อปี ความผันผวนรายปีคำนวณจากความผันผวนรายวันคูณรากที่สองของ 252

**Q26: Historical Bootstrap Monte Carlo สุ่มอย่างไร?**

แนวตอบ: สุ่มเลือกผลตอบแทนรายวันจากชุดผลตอบแทนในอดีต แล้วนำมาคูณกับมูลค่าพอร์ตปัจจุบันทีละวัน ทำซ้ำหลายวันและหลาย simulation

### คำถามเกี่ยวกับ risk_report.py

**Q27: Probability of Loss คำนวณอย่างไร?**

แนวตอบ: นับจำนวนเส้นทางจำลองที่มูลค่าสุดท้ายต่ำกว่าเงินลงทุนเริ่มต้น แล้วหารด้วยจำนวนเส้นทางจำลองทั้งหมด

**Q28: Maximum Drawdown ต่างจากการขาดทุนเทียบกับเงินลงทุนเริ่มต้นอย่างไร?**

แนวตอบ: Drawdown วัดการลดลงจากจุดสูงสุดก่อนหน้าในเส้นทาง ส่วนการขาดทุนเทียบกับเงินเริ่มต้นเปรียบเทียบมูลค่าสุดท้ายกับเงินลงทุนแรกเริ่ม จึงเป็นคนละมุมมอง

**Q29: ทำไม calculate_percentile() ต้องรับข้อมูลที่เรียงลำดับแล้ว?**

แนวตอบ: เพราะการหาตำแหน่งเปอร์เซ็นไทล์อาศัยลำดับจากน้อยไปมาก หากไม่เรียงก่อน ค่าที่เลือกหรือ interpolate อาจไม่ใช่เปอร์เซ็นไทล์ที่ถูกต้อง

**Q30: generate_report() รับข้อมูลอะไร?**

แนวตอบ: รับ dictionary ชื่อ analysis ซึ่ง main.py รวบรวมผลจากการวิเคราะห์และการประเมินความเสี่ยงไว้ แล้วจัดข้อความและบันทึกลงไฟล์รายงาน

### คำถามเชื่อมโยงทั้งระบบ

**Q31: ถ้าเปลี่ยนชื่อ key ใน dictionary ผลกระทบอาจเกิดที่ไหน?**

แนวตอบ: ต้องตรวจทั้งจุดที่สร้าง dictionary และทุกจุดที่อ่าน key นั้น เช่น main.py สร้างข้อมูล analysis และ risk_report.py นำ key ไปสร้างรายงาน หากเปลี่ยนเพียงฝั่งเดียวอาจเกิด KeyError หรือข้อมูลในรายงานหาย

**Q32: ถ้าฟังก์ชันหนึ่ง return ค่าเป็นชนิดข้อมูลผิดจากที่ผู้เรียกคาดไว้จะเกิดอะไรขึ้น?**

แนวตอบ: โค้ดถัดไปอาจใช้ข้อมูลนั้นไม่ได้ เช่น คาดหวัง list แต่ได้รับ None หรือ string จึงควรตรวจ input/output และสัญญาการทำงานของฟังก์ชันที่เชื่อมกัน
